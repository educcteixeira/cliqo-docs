# `POST /v1/contacts`

Cria um contato. Se o e-mail já existir **na mesma marca**, atualiza em vez de
duplicar.

**Escopo exigido:** `escreverContatos`.

```bash
curl -s -X POST https://app.cliqo.io/v1/contacts \
  -H "Authorization: Bearer cliqo_<sua-chave>" \
  -H "Content-Type: application/json" \
  -d '{"email":"cliente@exemplo.com","name":"Cliente","opt_in":true}'
```

## Corpo

| Campo | Tipo | Obrigatório | Nota |
|---|---|---|---|
| `email` | string | **sim** | Normalizado: espaços removidos, minúsculas |
| `name` | string | não | Nome completo |
| `phone_whatsapp` | string | não | Necessário se `whatsapp_opt_in` for `true` |
| `tags` | string[] | não | Valores não-string são descartados |
| `custom_fields` | objeto | não | Campos personalizados da conta |
| `source` | string | não | Padrão `api`; até 50 caracteres |
| `opt_in` | boolean | não | Declara opt-in de **e-mail marketing** |
| `whatsapp_opt_in` | boolean | não | Declara opt-in de **WhatsApp marketing** |

## A marca não é escolhida por quem chama

O contato nasce na marca da **chave**. Isso é deliberado: sem essa regra, a chave
de uma integração poderia gravar na base de outra marca da mesma conta.

## Erros deste endpoint

| Código | HTTP | Quando |
|---|---|---|
| `EMAIL_INVALID` | 400 | E-mail ausente ou sem `@` |
| `WHATSAPP_OPTIN_WITHOUT_PHONE` | 400 | `whatsapp_opt_in: true` sem `phone_whatsapp` |
| `CONTACT_SUPPRESSED` | 409 | O e-mail está na lista de supressão |
| `CONTACT_UPSERT_FAILED` | 500 | Falha ao gravar |
| `SUPPRESSION_LOOKUP_FAILED` | 503 | Não conseguimos consultar a supressão — tente de novo, não contorne |

<Warning>
**`CONTACT_SUPPRESSED` — leia antes de integrar.**

Se o e-mail foi descadastrado ou excluído, a criação é recusada com `409`. Não é
falha da sua integração: sem essa guarda, um sync recriaria como ativo justamente
quem pediu para sair — em lote e em silêncio.

Trate `409` como "este contato optou por sair" e não tente contornar. Remover a
supressão é ato deliberado, feito no painel por uma pessoa.
</Warning>

<Warning>
**Sobre `opt_in` — isto tem peso legal.**

`opt_in: true` cria um **registro de consentimento**, com a origem gravada e o
identificador da chave no rastro. É esse registro que responde, numa auditoria de
LGPD, quem declarou o opt-in e por qual porta.

Só mande `true` se o consentimento foi de fato coletado. E um contato criado com
`opt_in: true` pode entrar num fluxo de boas-vindas e receber e-mail — para carga
inicial de base, **prefira a importação de CSV do painel**.
</Warning>
